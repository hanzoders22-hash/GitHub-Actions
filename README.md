# Практична робота: Створення базового пайплайну GitHub Actions

## Мета роботи

Ознайомитися з принципами безперервної інтеграції (CI — Continuous Integration) та навчитися налаштовувати автоматизований пайплайн GitHub Actions для Node.js-проєкту.

## Опис проєкту

Проєкт є простою програмою на Node.js, яка виводить повідомлення `Hello world`. Для автоматизації перевірки використовується GitHub Actions.

Структура проєкту:

- `index.js` — головний файл програми.
- `src/message.js` — модуль, який містить текст повідомлення.
- `package.json` — файл із налаштуваннями проєкту та командами.
- `.github/workflows/ci.yml` — конфігурація автоматизованого CI-пайплайну.
- `.gitignore` — список файлів і папок, які не потрібно додавати до репозиторію.

## Використані технології

- Node.js — середовище виконання JavaScript.
- npm — менеджер пакетів.
- Git — система контролю версій.
- GitHub — платформа для зберігання коду.
- GitHub Actions — засіб автоматизації CI-процесів.
- YAML — формат опису конфігурації пайплайну.

## Налаштування GitHub Actions

Файл `.github/workflows/ci.yml` налаштований на автоматичний запуск після кожного `push` до гілки `main`.

Пайплайн виконує такі дії:

1. Завантажує код репозиторію.
2. Встановлює Node.js версії 22.
3. Виконує `npm install` для встановлення залежностей.
4. Запускає `npm run build` для перевірки та виконання програми.
5. Підготовлює файли проєкту для збереження.
6. Завантажує артефакт із назвою `nodejs-build`.

Якщо будь-який із необхідних кроків завершується помилкою, виконання пайплайну позначається як невдале.

## Запуск програми

Для локального запуску необхідно встановити Node.js, відкрити термінал у папці проєкту та виконати команди:

```bash
npm install
npm run build
npm start
```

Очікуваний результат:

```text
Hello world
```

## Перевірка результатів

Результат виконання автоматизованого пайплайну можна переглянути у вкладці **Actions** репозиторію GitHub.

Успішне виконання підтверджується зеленою галочкою біля запуску workflow. Артефакт `nodejs-build` можна завантажити на сторінці відповідного запуску.

## Висновок

Під час виконання практичної роботи було створено базовий CI-пайплайн за допомогою GitHub Actions для Node.js-проєкту. Налаштовано автоматичний запуск після надсилання змін до гілки `main`, встановлення середовища Node.js, виконання команди збірки та збереження артефакту. Це дозволяє автоматизувати базову перевірку проєкту та швидше виявляти помилки.
